# 工厂半成品转序与工艺参数锁定系统

操作员完成当前工序后登记产出（合格 / 返工 / 报废），质检员确认放行，下一工位接收时可查到该批半成品
**实际锁定的工艺参数版本**。批次拆分、报废、返工回流始终沿同一生产单关联，形成不中断的追溯链。

- 后端：PHP 8 + Laravel + Eloquent
- 前端：React + Vite（React Router，无第三方 UI 库）
- 存储：SQLite（工序、设备、数量、参数版本、追溯事件全部入库）
- 设备读数：本地模拟器（按锁定版本设定值 ±漂移生成，可手填或注入扰动）

## 业务流程与界面

1. **生产看板**：新建生产单 → 自动生成根批次；下发后首工位可见。
2. **工位工作台**：接收排队/在途批次（接收瞬间锁定该工序当前生效参数版本）→
   模拟/录入设备读数 → 登记合格·返工·报废数量 → 工序图显示批次当前所在设备、工序和参数版本。
3. **质检放行**：质检员处置数量（放行/返工/报废，合计必须等于投入）；放行后生成在途转序单，
   下一工位才能接收；可指定返工回流工序。
4. **待处理**：数量不符 / 参数超限的批次停在此处，**不得转给下一工位**；
   支持更正登记、短缺计报废、让步放行（留痕）、整批返工、整批判废。
5. **工艺参数**：工程师新建版本并激活完成换版；版本激活后不可变。
6. **追溯链**：批次树（根批 → 拆分/返工/判废子批）、事件时间线、数量守恒核对结果。

## 核心规则实现

所有状态变更均在数据库事务中对批次/转序单加行锁（`lockForUpdate`），每次移动写 `trace_events`。

- **数量核对**：登记时 `合格+返工+报废` 必须等于投入；不符 → `on_hold(qty_mismatch)`，禁止流转。
  质检处置同样强制合计守恒。
- **参数超限**：实测读数超出**批次锁定版本**的上下限 → `on_hold(params_out_of_range)`，禁止流转。
- **参数换版锁定**：接收时把 `parameter_versions.id` 固化到批次与每条产出登记；
  之后全局换版（旧版本 retired、新版本 active）不改变在制批次的判定基准与历史显示。
- **权责分离**：`qc_inspections.inspector_id != production_records.operator_id`，操作员自批直接拒绝。
- **工位占用互斥**：批次放行后产生 `pending` 转序单，仅目标工位可接收；
  在制批次绑定工位，其他工位占用被拒绝；同一设备同时只能加工一批。
- **拆分与返工沿原单**：子批次 `production_order_id`/`root_batch_id` 不变，
  批次号带 `-S/-R/-X` 后缀（拆分/返工/判废），拆分数量之和必须等于父批次。
- **返工回流**：生成返工子批回到指定工序排队，重新接收时锁定该工序当时生效版本，
  沿正常路线再次通过原缺陷工序后返工单自动关闭（done）。

## 数量守恒模型

```
计划数量 = 在制数量 + 完工数量 + 报废数量   （任意时刻成立）
拆分：父批数量 = Σ子批数量（后续子批报废也计入守恒核对）
返工：返工量 = 回流批次现存 + 回流批次报废
```

`/api/orders/{id}/trace` 的 `reconciliation` 与 `php artisan verify:workflow` 都会逐条核对上述等式。
